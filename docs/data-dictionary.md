# Data dictionary

## Input and cleaned transactions

One row represents a retained purchase line, not an order or customer. Multiple lines can share an invoice. Canonical names are below; UCI names in parentheses are accepted during import.

| Field | Type / unit | Meaning and handling |
|---|---|---|
| `invoice_no` (`InvoiceNo`) | Text | Order identifier; preserve leading zeros; cancellation IDs starting with `C` are excluded |
| `stock_code` (`StockCode`) | Text | Product identifier; retained codes begin with a digit or `P` followed by a digit |
| `description` (`Description`) | Text | Product label; missing values become `Unknown product` |
| `quantity` (`Quantity`) | Positive integer | Units purchased; noninteger, nonfinite, nonpositive and >2,147,483,647 values excluded |
| `invoice_date` (`InvoiceDate`) | Timestamp | Source-local purchase time; invalid dates excluded; timezone-aware inputs rejected |
| `unit_price` (`UnitPrice`) | GBP / unit | Positive finite price, capped at 99,999,999 at cleaning; rounded to two decimals; values rounding to zero excluded |
| `customer_id` (`CustomerID`) | Nullable text | Known customer identifier; missing allowed; imported integer-like `.0` suffix removed |
| `country` (`Country`) | Text | Transaction country; missing values excluded |
| `revenue` | GBP | Derived via integer cents; lines over GBP 9,999,999,999.99 excluded before multiplication |

Strings are stripped. Missing invoice, stock, country or valid date excludes the row. Exact duplicates are removed before other exclusions. Exclusion counts are sequential: each removed row is counted once under the first matching rule. An invoice with inconsistent countries or customer IDs raises an error rather than producing ambiguous order metrics.

The product-code rule is tailored to the demonstration/UCI source and is not a universal merchandise classifier. Review this rule before integrating another retailer. Exact repeated rows might represent genuine repeated lines in another source; confirm the source's line key before applying deduplication there.

## Metrics

| Metric | Definition |
|---|---|
| Revenue | Sum of retained positive purchase line revenue |
| Orders | Number of distinct invoice numbers in the current scope |
| Average order value | Revenue divided by orders; undefined if no orders |
| Units | Sum of quantity |
| Known customers | Distinct nonempty customer IDs |
| Repeat customer | Known customer with more than one distinct order in the selected observation window |
| Repeat customer rate | Repeat known customers divided by all known customers |
| Recency | Days from last purchase to one day after the dataset's final purchase |
| Frequency | Distinct observed orders per known customer |
| Monetary | Retained purchase revenue per known customer |

Refunds and cancellations are not subtracted from revenue. This is not accounting net sales, tax-adjusted revenue or realized profit. No cost, category hierarchy, inventory balance, supplier lead time or verified acquisition date is available.

## Warehouse tables

`dim_product(stock_code, description)` holds each stock code once. Its description is the latest observed label, with a deterministic alphabetical tie-break. `dim_customer(customer_id)` contains known IDs only. `dim_date(date, year, month, day_of_week)` is continuous over the observed range; weekday 1 is Monday. `fact_sales` stores snapshot-local `line_id`, invoice/product/customer identifiers, sale date, source timestamp, country, quantity, decimal price and decimal revenue. Nullable customer keys preserve anonymous purchases.

The warehouse stores money as `numeric`, validates positive purchases and revenue reconciliation, and enforces dimension foreign keys. Do not reuse snapshot line IDs as durable business keys.

## Audit and provenance

`quality_report.json` records row reconciliation, anonymous row count and total retained revenue. `manifest.json` records `source` (`synthetic` or `external`), GBP currency, seed for demo data, input hash when external, cleaned CSV hash, observation dates and metric scope. Hashes identify exact files, not their truthfulness or license. `forecast_metrics.json` documents chronological folds and holdout scores; see the forecasting guide.
